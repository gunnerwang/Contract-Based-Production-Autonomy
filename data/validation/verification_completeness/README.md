# Verification completeness and corrected lifecycle checks

Run `python scripts/validate_corrected_lifecycles.py` from the repository root. No LLM API calls or external services are used. The cell uses SimPy and the factory uses the analytical evaluator, with seed 42 and the optional macro phase.

One execution per configuration: cell anchors halt at phase 5 with phases 1–4 completed and no accepted experience recorded; cell anchors plus optimizer complete phases 1–6; both factory pools complete phases 1–6. `lifecycle_summary.json` contains metrics of completed phases, outcomes, and hashes of all implementation files. Per-run audit JSON and logs are retained in separate directories.

These are controlled executions of corrected control flow, not comparative performance estimates, reruns of archived LLM dialogues, or physical-safety validation. The archived LLM call logs contain statistics but not full responses, so they cannot reconstruct those dialogues. The original experiment batches remain unchanged.

`python -m pytest tests -q --disable-warnings` checks unknown fields, unsupported operators, empty/duplicate obligations, non-finite limits/readings, missing measurements/operators/cell evaluators, partial factories, exact report/contract coverage, a single incomplete sample despite p=.995, both candidate gates, both certified optimizers, and dispatch refusal. The current full suite passes 318 tests; `../fail_closed/test_results.txt` records the result.

The runtime guard follow-up synthesizes all supported encoded obligations, uses the verifier's comparison and metric semantics, and aborts on missing/non-finite readings or hard violations without rewriting measurements. The simulated cyber-risk level is explicitly supplied; absent input fails. Factory phase 2 checks an analytical snapshot, SimPy checks end-of-shift metrics, and integration checks every collected poll using raw sensor readings (missing values, model substitutes, and unavailable throughput/energy/defect/deadline observations cannot pass). Runtime failures propagate without fallback and are audited as `runtime_execution_blocked`; software abort is not physical stopping. `tests/test_runtime_guards.py` contains 63 focused regressions; `tests/test_runtime_guard_integration.py` adds 15 mocked sensor/integration regressions. The controlled lifecycle outputs and source hashes were refreshed after this correction.

The comprehensive follow-up adds 38 cross-path regressions for service failure states (including escalation completion), canonical audit paths, accepted-learning timing, repeated contract validation and preservation, mandatory upper-bound directions, zero/non-finite assumption observations, absence-planning semantics, grounded nullable attribution, and refusal after integrated execution errors. These corrections are included in the refreshed controlled-run source hashes.
